### Public API stability

- `ferrum_lifespan`: extended with optional keyword-only arguments
  (`acquire_timeout`, `drain_timeout`, etc.); all default to `None` or
  prior values. Backward compatible — existing callers pass only
  `database_url`/`min_size`/`max_size` and behave identically.
- `get_ferrum_conn`: parameter annotation changed from `FerrumConnRequest`
  (Protocol) to `_StarletteRequest` (concrete `starlette.requests.Request`
  with `Any` fallback when Starlette absent). Runtime behavior unchanged
  for callers passing a Starlette `Request`; the `FerrumConnRequest`
  Protocol is retained for static type-checking documentation. The
  executor documented this deviation (FastAPI DI requires the concrete
  type to recognize the parameter as the ASGI request). Ferrum is alpha
  with no semver contract (AGENTS.md §5a), so the annotation change is
  within policy. Not a blocker.
- New public surface: `get_ferrum_transaction`, `map_ferrum_to_http_status`,
  `ferrum_exception_handler`, `register_ferrum_exception_handlers`,
  `FerrumUserDatabase` — all additive, no removals.
- `python/ferrum/__init__.py` `"contrib"` export unchanged.

### Non-blocking observations

1. **`get_ferrum_conn` annotation change** (noted above): the
   `FerrumConnRequest` Protocol → `_StarletteRequest` swap is a public
   annotation change. It is justified, documented, runtime-preserving,
   and within alpha policy. A future tightening could restore the
   Protocol as the annotation and use a `Depends` marker, but the
   current approach is the standard FastAPI pattern.
2. **`Any` prevalence in `FerrumUserDatabase`**: the adapter types
   `user_model`/`oauth_account_model`/return values as `Any` with
   `# noqa: ANN401`. This is the right call for a soft-import boundary,
   but a future typed `ferrum.Model` Protocol (with `.objects: QuerySet`)
   would let the adapter expose real types without a hard dep. Not
   required for v0.1.
3. **`eval()` in subprocess boundary tests** (`# noqa: S307`): the
   checked output is a printed Python list literal from our own
   subprocess. `ast.literal_eval` would be a minor defense-in-depth
   hardening; not required.
4. **Integration test breadth**: `FerrumUserDatabase` has no live
   integration test (would require `fastapi-users` installed). The unit
   tests cover the soft-import failure mode and the two translation
   paths (`get_by_id`→None, `create`→UserAlreadyExists) with fakes.
   Acceptable for an optional adapter whose host owns the fastapi-users
   version pin.
