### Rust benchmark quality (code review)

- **Sample sizes:** `hydrate` groups use `sample_size(50)` (rows vary 1–1000);
  `compile_select`/`compile_write` use `sample_size(100)` (fast, sub-ms); bulk
  uses `sample_size(50)` (10–1000 rows). Appropriate for the cost profile.
- **Warm-up / measurement:** 300–500ms warm-up, 3s measurement — reasonable for
  local CI; nightly can extend.
- **`black_box` usage:** every `emit_*` and `hydrate_rows` call wraps both
  metadata and IR/rows in `black_box`, preventing the optimizer from pre-computing
  the result. Correct.
- **`iter_batched`:** hydration benches clone the row batch per iteration
  (`BatchSize::SmallInput`) so `hydrate_rows` consumes fresh owned input —
  matches the runtime contract (fresh owned output per call, §2.10). The
  `json_boundary` encode bench clones via `serde_json::to_vec` in the setup
  closure — correct isolation of serialization cost.
- **`validation_copy` design:** same `make_wide_rows(100)` input, two metadata
  variants (`wide_metadata(true)` vs `wide_metadata(false)`). The delta is the
  validation walk. Clean differential measurement.
- **`#![allow(clippy::pedantic)]`:** documented, scoped to bench harness,
  `clippy::all` stays enforced. Consistent with project convention.

### Python test quality (code review)

- **`Sample` dataclass:** typed, documented, captures all six required metrics
  plus `extra` for workload-specific fields. `asdict` serialization for
  `perf.json` is clean.
- **`run_workload`:** warmup loop discarded; `tracemalloc` + `resource.getrusage`
  + `time.perf_counter` capture CPU/memory/latency; pool snapshot via callback.
  Percentile calculation uses sorted-index interpolation. Correct.
- **`_compare_baseline`:** soft — prints regressions, never raises. The
  `REGRESSION_FACTOR` (default 3.0) is configurable via env. Matches the
  task contract's "report, never hard-fail."
- **`_assert_no_crash`:** the only hard assertion — `throughput_ops_per_s > 0`
  and `p50_us > 0`. These are crash/zero-throughput checks, not latency gates.
  The `test_no_hard_latency_gates` regex (`[<>]\s*[1-9]\d*`) correctly does NOT
  match `> 0` (zero is not `[1-9]`). Verified.
- **`bench_env` fixture:** function-scoped (documented: avoids pytest-asyncio
  loop-scope mismatch with asyncpg pool). Reads `FERRUM_TEST_DSN` directly
  rather than the function-scoped `pg_dsn` fixture — documented design decision.
  Teardown drops tables and closes pools in `finally`. Clean.
- **`test_bench_wire_format_boundary`:** opens a separate msgpack connection
  and restores `FERRUM_WIRE_FORMAT` in `finally`. No env-var leakage.
- **`test_rust_benchmarks_compile`:** the lib-error skip workaround
  (`"could not compile \`ferrum-sql\` (lib)"` with bench code not the cause)
  is a pragmatic, documented guard against parallel-workstream lib compile
  blockers. Acceptable — the bench code itself compiles cleanly when the lib
  is healthy.
