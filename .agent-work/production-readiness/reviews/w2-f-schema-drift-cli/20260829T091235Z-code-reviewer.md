## Findings

### MEDIUM — index column-order drift not detected

`_index_signature` at `python/ferrum/migrations/drift.py` sorts columns
alphabetically (`tuple(sorted(idx.get("fields") or ...))`). For btree
indexes, column order is semantically significant: `(status, priority)`
and `(priority, status)` are different indexes with different query-plan
behavior. The sort makes them compare as equal, so composite-index
column-order drift is silently masked. Reproduced above: 0 diffs for a
reversed composite index.

Acceptance criterion "Compare ... indexes/opclasses/predicates" is
partially unmet: columns are compared as an unordered set, not an ordered
list.

**Required correction:** remove `sorted()` from `_index_signature` — use
`tuple(idx.get("fields") or idx.get("columns") or ())` preserving
declaration order. Add a unit test: model declares
`Index(fields=("status", "priority"))`, live index has
`(priority, status)` → `missing_index` + `extra_index` diffs.

### MINOR — unused `table` parameter

`_compare_indexes(table: str, ...)` and `_compare_constraints(table: str,
...)` accept `table` but never reference it in the function body (confirmed
via AST). The caller passes `table` at the call site. Either use `table`
in diagnostic messages (e.g., `f"{table} index {name} ..."`) or remove the
parameter. Path: `python/ferrum/migrations/drift.py`.

### MINOR — verbose repeated `_row_values` calls in policies comprehension

The `policies` list comprehension in `_fetch_postgres_schema` calls
`_row_values(r, (8-tuple))` six times with the identical key tuple to
extract `schema`, `table`, `name`, `permissive`, `command`, `using`. Call
once, unpack into locals. Path: `python/ferrum/migrations/drift.py`
~lines 620–680.

### MINOR — dead `idx.get("columns")` fallback

`_index_signature` falls back to `idx.get("columns")`, but both expected
indexes (`_expected_indexes`) and live indexes
(`_fetch_postgres_schema`) use the `"fields"` key. The `"columns"`
fallback is dead code. Path: `python/ferrum/migrations/drift.py`
`_index_signature`.

### MINOR — vector dimension comparison non-functional live

`_vector_dimensions_from_udt` returns `column.get("dimensions")`, but the
`information_schema.columns` query does not populate a `dimensions` key
(it would require a `pg_attribute` join on `atttypmod`). The comparison
logic fires only when enriched; no integration test exercises it. The
live path is a no-op. Documented as follow-up by the executor. Path:
`python/ferrum/migrations/drift.py`. Acceptable as follow-up; add a unit
test that injects a `dimensions` key to cover the comparison path, or add
the `pg_attribute` join.

### MINOR — untested comparison paths

No test coverage for:
- `expected_policies` / `expected_functions` comparison paths
  (`_compare_policies` / `_compare_functions` missing-policy/function
  branches).
- FK constraint `delete_rule` drift (`_compare_constraints`
  `foreign_key_delete_rule` branch).

These code paths are implemented but untested. Smallest correction: add
unit tests that pass `expected_policies` / `expected_functions` and assert
`missing_policy` / `missing_function` differences; add a unit test with
expected FK `ON DELETE CASCADE` vs. live `ON DELETE NO ACTION`.
