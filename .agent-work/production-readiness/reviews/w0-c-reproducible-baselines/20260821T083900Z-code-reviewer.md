### Least Astonishment — `continue-on-error` vs `smoke-wheel` as a real gate

The split is the correct one:

| Step | `continue-on-error` | Why |
| --- | --- | --- |
| `mise run smoke-wheel` | **no** | Compiler-free wheel install (ADR-005 / release gate 7) is a correctness property, not noisy latency. A wheel that will not import without `rustc` is a real regression. |
| `mise run bench-rust` / `bench-python` / `baseline` | **yes** | Matches W4-B and the task non-goal: no hard threshold until variance is measured. Python benches currently fail on unowned `_pool` access; that must not fail Nightly. |

A failed `smoke-wheel` fails the `reproducible-baseline` **job** and therefore
the Nightly **workflow**, and does **not** block PR CI: Nightly never runs on
`pull_request`, and `ci.yml` ignores `nightly.yml` path-only changes. Editing
`mise.toml` / `benchmarks/` / `tests/benchmarks/` still runs PR CI, which is
the right Blast Radius — source changes are gated; cron benchmark noise is not.

`pytest` marker `benchmark: performance benchmarks (not a blocking gate)`
(`pyproject.toml:178`) already documented that policy; the new job matches it
for benches and carves out wheel smoke as the exception.

### Warnings

1. **Nightly “aggregate” step will often produce no `baseline.json`.** The step
 named “Aggregate reproducible baseline report” runs `mise run baseline`,
 whose `depends` re-runs `test-consumer-contracts`, `smoke-wheel`,
 `bench-rust`, and `bench-python`. Mise short-circuits on a failed depend.
 With `unowned-benchmark-pool-attribute-bug` still open, `bench-python`
 fails, aggregation never runs, and `continue-on-error` only keeps the job
 green. `if: always()` still uploads whatever `benchmarks/latest/` already
 holds (smoke-wheel outputs; maybe a partial pytest-benchmark JSON).
 **Least Astonishment:** the step name promises a report; the command
 re-executes the full graph. Should-fix: last step should invoke
 `python3 benchmarks/collect_baseline.py ...` (or a no-depends collect
 task) against artifacts already written, so a partial p50/p95/p99 report
 still lands. Do not treat this as a W0-C ownership expansion into
 `tests/python/benchmark/`.

2. **Unproven CI bootstrap for the only hard gate.** `reproducible-baseline`
 is the first `jdx/mise-action@v2` use in this repo. Other jobs
 `pip install maturin` and `pip install -e ".[dev]"`. `smoke_wheel.sh`
 prefers `uv run --project … maturin`; `maturin` lives in the `dev` extra
 (`pyproject.toml:69-71`), and there is no `[tool.uv]` default-extra.
 Local `mise run smoke-wheel` works on a pre-synced venv; a cold runner
 may fail `smoke-wheel` for missing `maturin`, which would red the Nightly
 workflow every night without proving a wheel defect. Should-fix: `uv sync
 --extra dev` (or `uv run --extra dev maturin`) before the gate, matching
 `mise run setup`. Executor already recorded that GHA has not been
 dispatched; verifier should `workflow_dispatch` rather than trusting YAML
 parse + local runs.

### Suggestions

- Do not add `test-benchmarks-harness` to `ci-local` (explicitly out of
 scope). Optionally run it as a cheap extra nightly step (no DB, 11 tests);
 today neither PR CI nor Nightly runs those harness unit tests.
- `smoke_wheel.sh` comments that the install venv has no `cargo` on PATH;
 venv activation only prepends `venv/bin` — runner `~/.cargo/bin` remains.
 `pip install` of a `.whl` still does not compile. Stripping `cargo`/`rustc`
 from PATH during install would make the compiler-free claim stricter.
- Deduplicate CI: first `smoke-wheel` / `bench-*` already ran; `mise run
 baseline` re-runs them. Direct `collect_baseline.py` also fixes warning 1.
- `mise.toml:187-188` still says Nightly “runs the bench-* pair”; the new
 job also runs `smoke-wheel` and `baseline`. Comment drift only.
- Pin `jdx/mise-action` to a SHA when convenient; major-tag pin matches
 `Swatinem/rust-cache@v2` / `dtolnay/rust-toolchain@master` already in-tree.
- Raw `bench-python.json` `machine_info.node` is a hostname
 (`IL-GUYS-MBP.local` on the local artifact). Aggregated `baseline.json`
 does not copy it. Not a secret; fine for a public artifact.
