## Findings

### F1 — Minor: `_acquire_cm()` seam not used consistently (DRY)

- Severity: minor (non-blocking)
- Path: `python/ferrum/drivers/postgres.py:444-451` (`open_stream._source`),
  `:464-469` (`acquire`), `:500-511` (`transaction`).
- Evidence: `_acquire_cm()` was introduced as "the single acquire seam" and
  is used by `fetch`/`fetchrow`/`fetchval`/`execute`. However,
  `open_stream()`, `acquire()`, and `transaction()` duplicate the
  `if self._acquire_timeout is not None: pool.acquire(timeout=...) else:
  pool.acquire()` branch inline instead of calling `_acquire_cm()`.
- Impact: timeout is still enforced on every path (verified — C1 PASS), but
  the timeout logic is not single-sourced. A future change to the acquire
  seam would need to be applied in four places.
- Recommended correction (optional, non-blocking): replace the inline branch
  in all three with `async with self._acquire_cm() as raw_conn:`. The helper
  returns an async context manager in both branches, so the substitution is
  mechanical.

### F2 — Minor: inline comments added to `postgres.py` where base had none

- Severity: minor (non-blocking)
- Path: `python/ferrum/drivers/postgres.py` (~12 new inline `#` comment lines).
- Evidence: base `drivers/postgres.py` had 0 inline comments; W1-E adds ~12
  explanatory comments (legacy aliasing, birth-time tracking, force-terminate
  reasoning, defensive getattr). The broader codebase (`queryset.py` 92,
  `errors.py` 34, `orchestrator.py` 78 inline comments) does use inline
  comments, and `connection.py` (base) already had inline comments.
- Impact: AGENTS.md §8 lists "No unnecessary comments" as a definition-of-done
  item. These comments explain non-obvious WHY (not restating code), so they
  are defensible, but they introduce a new convention into a file that
  previously had none. Not a blocker.
- Recommended correction (optional): trim to the most essential (legacy
  alias, force-terminate rationale) and rely on docstrings for the rest.

### F3 — Minor: no integration test for `open_stream` + `acquire_timeout`

- Severity: minor (non-blocking; already noted as F1 by the verifier)
- Path: `tests/python/integration/` — no test saturates a pool and verifies
  `open_stream` raises `FerrumTimeoutError` on acquire timeout.
- Evidence: `grep -rn "open_stream" tests/python/integration/` returns no
  saturation+timeout test. The implementation enforces the timeout
  (`postgres.py:444-445`).
- Impact: coverage gap only; implementation is correct. Acceptance criterion
  C1 is satisfied at the implementation level.
- Recommended correction (optional): add an integration test that saturates
  a `max_size=1` pool and verifies `open_stream` honors `acquire_timeout`.

### F4 — Informational: `drain_inflight` now dead code in `runtime.py`

- Severity: informational
- Path: `python/ferrum/runtime.py:236` — `drain_inflight` is still defined but
  has no remaining callers (`connection.py` no longer imports it).
- Evidence: `grep -rn "drain_inflight" python/` returns only the definition
  in `runtime.py` and docstring references in `connection.py`.
- Impact: none. W1-E correctly did not remove it (`runtime.py` is not an
  owned path — scope discipline). A future cleanup can remove it.

### F5 — Informational: test redundancy across the two integration files

- Severity: informational
- Path: `tests/python/integration/test_connection.py` and
  `test_connection_runtime.py` both add PoolStats/growth/shutdown/stale tests
  with overlapping coverage (e.g., `test_pool_stats_typed_snapshot` vs
  `test_pool_stats_returns_typed_snapshot`; `test_pool_growth_under_load` vs
  `test_pool_growth_from_min_to_max`).
- Impact: none — tests follow different file themes and reinforce coverage.
  Slightly redundant but not a defect.

### F6 — Informational: `id(conn)` key reuse in `_conn_birth_times`

- Severity: informational (documented limitation)
- Path: `python/ferrum/drivers/postgres.py:291` —
  `driver_ref._conn_birth_times[id(conn)] = time.monotonic()`.
- Evidence: `id()` can be reused after GC. Mitigated by the pool holding
  references and `_conn_birth_times.clear()` on close. Acceptable for
  best-effort `max_connection_age` enforcement (documented in the executor
  log as best-effort).
