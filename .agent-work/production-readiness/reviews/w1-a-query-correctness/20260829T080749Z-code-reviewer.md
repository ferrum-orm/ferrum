## Findings

### Minor (non-blocking) — vacuous mock assertion

`tests/python/security/test_sql_safety.py:473-479`
`test_compile_mock_not_called_on_rejection`:

The test monkeypatches `qs._compile` and then calls
`qs.filter(injected_field="value")._build_ir()`. Two issues make the
`compile_mock.assert_not_called()` assertion vacuously true:
1. `filter()` returns a clone (`queryset.py:719`) with its own unmocked
   `_compile` — the mock is on the original `qs`, not the clone.
2. `_build_ir()` never calls `_compile()` — it is the other way around
   (`_compile()` calls `_build_ir()`, queryset.py:1065).

The test passes and `FerrumCompileError` is correctly raised by Stage-0
(`_q_to_predicate` at `filter()` time, queryset.py:723), but the mock
assertion does not verify what the docstring claims ("the Rust compiler is
never called"). Suggested fix: monkeypatch the Rust native entry point
(`_native_ext.compile_query`) and call `_compile()` on the filtered clone,
or drop the mock assertion since the surrounding fuzz tests already prove
Stage-0 rejection. Not blocking — the test does not produce a false pass
for any real defect; it simply adds no incremental coverage.

### Minor (non-blocking) — test overlap

`tests/python/unit/test_queryset_guards.py:240-316`: the 6 new
sliced/limit/offset tests overlap with the pre-existing
`test_sliced_delete_raises` (line 168, uses `[:10]`) and
`test_sliced_update_raises` (line 177, uses `.offset(5)`). The new tests
are more granular (separate limit vs offset vs slice-shorthand) which has
marginal value, but the redundancy is noted. Not blocking.

### Info — misleading docstring

`tests/python/security/test_sql_safety.py:494-501`
`test_no_sql_text_produced_for_rejected_operator`: docstring says
"confirming _build_ir() raises before _compile() is reachable" — trivially
true since `_build_ir()` never calls `_compile()`. The test itself is valid
(verifies `_build_ir()` raises on a bad operator) but the docstring
overstates what it proves. Not blocking.
