## Findings

### #1 — HIGH (was: metric handlers cross-contaminate by event type) — RESOLVED

`python/ferrum/observability.py` `enable_metrics()` now registers each handler
for its specific event(s) instead of `"*"`. Only `_on_pool_event` remains on
`"*"` and guards internally via `metric_map.get(event)` → early return.
Empirically confirmed: dispatching `query_success` no longer inflates
`ferrum.transaction`/`ferrum.migration`/`ferrum.retry`/`ferrum.timeout`.
Regression tests: `test_query_dispatch_does_not_inflate_non_query_metrics`,
`test_pool_dispatch_does_not_inflate_query_metrics`,
`test_transaction_dispatch_does_not_inflate_query_metrics`. All pass.

### #2 — MEDIUM (was: no behavioral test for span-around-query) — RESOLVED

`TestOTelSpanLifecycle` added with 3 tests using a fake in-memory OTel tracer
(`_FakeTracer`/`_FakeSpan` injected via `sys.modules` monkeypatch):
- `test_query_success_creates_span_with_duration` — exactly one span named
  `ferrum.query`, `span.ended is True`, `duration_ms` attribute present,
  `_active_query_span` cleared.
- `test_query_failure_creates_span` — same for the failure path.
- `test_orphan_success_creates_fallback_span` — `query_success` without
  `query_start` creates a fallback span that is ended.

Note (residual, non-blocking): the finding suggested `opentelemetry-sdk`'s
`InMemorySpanExporter`, but that package is not a dev extra and `pyproject.toml`
is outside owned paths. The mock-based approach exercises the observability
bridge logic (span lifecycle, contextvar clearing, orphan fallback) — the
finding's intent (behavioral coverage of span-around-query) is satisfied. A
real-SDK test would require adding `opentelemetry-sdk` to dev deps in a
follow-up.

### #3 — LOW (was: duplicate HELP/TYPE in Prometheus exposition) — RESOLVED

`render_prometheus()` now groups `_METRICS` keys by family (substring before
`{`), emits `# HELP`/`# TYPE` once per family, then all samples. Regression
test `test_render_prometheus_help_type_once_per_family` dispatches 2
`query_success` events with different operations and asserts `# HELP`/`# TYPE`
appear exactly once for `ferrum_query_count`. Empirically confirmed.

### #4 — LOW (was: pool gauge metrics accumulate instead of setting) — RESOLVED

`set_gauge(name, value, labels=)` assigns (`=`) instead of accumulating.
`_on_pool_event` calls `set_gauge` for `pool_size`/`pool_idle`/
`pool_acquired_count`/`pool_waiters`. Empirically confirmed: two `pool_acquire`
events with `pool_size` 10 then 8 produce `ferrum.pool.size == 8.0`, not 18.0.
Regression tests: `test_pool_gauge_sets_not_accumulates`,
`test_set_gauge_overwrites_not_accumulates`. Both pass.

### #5 — INFO (dangling comment in OTel query span block) — NOT FIXED (out of scope)

`observability.py` `_otel_hook` still contains the dangling comment
`# Record a span event for hydration failures paired with a query.` with no
corresponding code. This is an INFO nit explicitly outside the corrective scope
(findings #1–#4 only). Non-blocking; deferred to a future cleanup.

### #6 — INFO (transaction OTel span is zero-duration) — NOT FIXED (out of scope)

`observability.py` `_otel_hook` `transaction_start` branch still creates a
