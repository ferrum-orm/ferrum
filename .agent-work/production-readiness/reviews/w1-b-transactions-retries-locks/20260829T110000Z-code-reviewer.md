### Public API stability

Additive only:
- `Connection.run_transaction(fn, *, isolation, readonly, deferrable, deadline, retry)` — new method.
- `Connection.advisory_lock(key)` — new async context manager.
- `Transaction.advisory_xact_lock(key)` — new method.
- `Transaction.advisory_try_xact_lock(key) -> bool` — new method.
- `QuerySet.select_for_update(*, nowait, skip_locked, of)` — new chaining method.
- `TimedQueryExecutor.__init__(..., is_transaction=False)` — new kwarg (default False).
- `TimedQueryExecutor.fetch/fetchrow/fetchval(..., is_write=False)` — new kwarg (default False).
- `TransactionRetryPolicy`, `AdvisoryLockKey` — new public dataclasses in `runtime.py`.

`RetryPolicy` behavioral change: `"connection"` removed from
`_RETRY_CATEGORIES`; `RetryPolicy.__post_init__` now rejects `on=...{"connection"}`
with `ValueError`. This is the **intended** §5a correction (a client timeout or
connection drop after server commit can duplicate writes), not a stability
regression — `connection` was never a safe statement-retry category. No
documented public API is removed or renamed.

## Findings

### Observation 1 (minor, non-blocking): `# type: ignore` on `is_write` calls

- **Severity:** minor (cosmetic / type-annotation gap)
- **Evidence:** `queryset.py:2269,2639,3019,3119,3439` use
  `# type: ignore` on `fetch`/`fetchrow` calls passing `is_write=True`. The
  `QueryExecutorProtocol` in `drivers/protocol.py` (not owned by W1-B) does not
  declare the `is_write` keyword arg, so `ty` flags it as `unknown-argument`.
  At runtime the object is always a `TimedQueryExecutor` which accepts
  `is_write`.
- **Required correction:** none for W1-B (the protocol file is outside owned
  paths). Follow-up for a future workstream: add `is_write: bool = False` to
  `QueryExecutorProtocol.fetch/fetchrow/fetchval` and remove the 5
  `# type: ignore` markers. The executor log already documents this as a
  follow-up.

### Observation 2 (cosmetic, non-blocking): inline `#` comments

- **Severity:** cosmetic
- **Evidence:** The diff adds several inline `#` comments (e.g.
  `runtime.py:46-49` "Per ratified §5a: ...", `runtime.py:117-119` "SQLSTATE
  codes that ...", `connection.py:676-677` "Honor cancellation ...",
  `queryset.py:731-733` "SELECT ... FOR UPDATE ... state"). AGENTS.md says
  "DO NOT ADD ANY COMMENTS unless asked." However, these comments explain
  non-obvious security/contract decisions (§5a binding rules, no-raw-SQL
  invariant, cancellation semantics) and several double as documentation for
  public API surfaces. The docstring expansions (module-level, class-level,
  method-level) are required per AGENTS.md §8 ("Public API changes require
  documentation updates").
- **Required correction:** none. The comments are substantive and aid
  maintainability of security-sensitive code. A stricter reading of the
  "no comments" rule could trim a few, but they do not violate the spirit of
  the rule (which targets noise, not contract explanations).

### Observation 3 (cosmetic, non-blocking): `AdvisoryLockKey` frozen-dataclass pattern

- **Severity:** cosmetic
- **Evidence:** `AdvisoryLockKey` is a `@dataclass(frozen=True)` with a custom
  `__init__` that uses `object.__setattr__(self, "_key", ...)` to set the
  private field. This is a known idiom for frozen dataclasses with validated
  construction. The leading-underscore `_key` field keeps the validation in
  `__init__` while `as_args()`/`is_two_part()` expose the public surface. No
  correction needed; noted for consistency awareness.
- **Required correction:** none.
