### Design decisions

1. **ConnectionInitializer protocol** lives in `python/ferrum/drivers/protocol.py` (owned). It is a
   `Protocol` with one async method `initialize(conn) -> None` plus a `name: str` attribute for
   diagnostics. The protocol is consumed by `AsyncpgDriver` (NOT modified here — W1-E already wires the
   pool `init` hook through `add_type_codec`). This task adds the *declarative* surface so consumer code
   can hand a list of initializers to `connect(...)` (documented, not implemented in `connection.py` —
   that path is shared/leased) and so a pgvector initializer can be invoked without leaking the raw
   asyncpg connection.

2. **Generalization**: the initializer protocol accepts the Ferrum `Connection` (typed as
   `ConnectionLike` so the protocol module does not import `connection.py` — keeps the import boundary
   clean). Consumer-defined initializers (citext, custom codecs) implement the same protocol.

3. **pgvector initializer**: a class `PgVectorInitializer` implementing `ConnectionInitializer`. It
   runs `CREATE EXTENSION IF NOT EXISTS vector` through the driver (not the raw pool — the existing
   `register_vector_codecs` reaches `driver._pool.execute`; the initializer instead uses
   `conn._require_driver().execute(...)`, the sanctioned QuerySet/migration seam, so it never exposes
   the raw asyncpg pool to consumer code). It then registers the vector codec via
   `driver.add_type_codec(...)`. Failure to create the extension fails-closed: the exception propagates
   (fail-closed contract — a pool that cannot install a required extension must not silently serve
   queries against vector columns).

4. **`register_initializers` helper**: a function on `Connection` is NOT in owned paths. Instead the
   public surface is `ferrum.ext.pgvector.PgVectorInitializer` plus a convenience
   `register_vector_codecs(conn)` (kept, now a thin wrapper that builds a `PgVectorInitializer` and
   runs it). Consumer-defined initializers can be invoked by application code via
   `await initializer.initialize(conn)` after `ferrum.connect()`.

5. **`connect(..., extensions=...)` documentation**: the task says "do NOT modify `connect()`". The
   initializer protocol is the contract that *would* be consumed by `connect()`; this run documents
   the intended usage in docstrings and the run log without touching `connection.py`. Application code
   today calls `await PgVectorInitializer().initialize(conn)` (or the legacy
   `register_vector_codecs(conn)`) after `async with ferrum.connect(...) as conn:`.
