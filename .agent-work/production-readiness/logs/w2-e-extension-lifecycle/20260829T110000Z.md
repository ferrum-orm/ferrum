## Defects addressed

### DEFECT-1 (medium) — docstring/implementation mismatch

**Claim**: `PgVectorInitializer` and `ConnectionInitializer` docstrings
stated that `CREATE EXTENSION` runs through the sanctioned
`conn._require_driver().execute(...)` seam. The actual implementation at
`python/ferrum/ext/pgvector.py:187` uses `await pool.execute(...)` — the
raw asyncpg pool — preserving the legacy `register_vector_codecs`
behavior.

**Fix (option a — owned-paths-only, docstrings only)**:

1. `python/ferrum/ext/pgvector.py:126-130` — `PgVectorInitializer` class
   docstring step 2 now reads: "Runs `CREATE EXTENSION IF NOT EXISTS
   vector` directly against the asyncpg pool
   (`conn._driver._pool.execute(...)`), preserving the behavior of the
   legacy `register_vector_codecs` helper."

2. `python/ferrum/drivers/protocol.py:94-102` — the comment block above
   `ConnectionLike = Any` now reads: "Implementations read `conn.dialect`
   for backend validation; the canonical `PgVectorInitializer` reaches the
   asyncpg pool directly (`conn._driver._pool.execute`) to preserve the
   legacy `register_vector_codecs` behavior, while consumer-defined
   initializers may use `conn._require_driver()`."

3. `python/ferrum/drivers/protocol.py:115-122` — the `ConnectionInitializer`
   class docstring "Initializers must:" list now reads: "Consume the
   `Connection` surface for backend validation (`conn.dialect`). The
   canonical `PgVectorInitializer` reaches the asyncpg pool directly
   (`conn._driver._pool.execute`) to preserve the legacy
   `register_vector_codecs` behavior; consumer-defined initializers may use
   `conn._require_driver()`. Never expose the raw asyncpg/aiomysql
   connection to consumer code."

   (The third location was not explicitly cited by the verifier but makes
   the same false claim as the cited two; fixing it for internal
   consistency so the protocol docstring does not contradict itself.)

### DEFECT-2 (low) — `name` attribute not runtime-enforced

**Claim**: `ConnectionInitializer` protocol declares `name: str` but
`@runtime_checkable` only checks method presence, not attribute presence.

**Fix**: Added a paragraph to the `ConnectionInitializer` class docstring
(`python/ferrum/drivers/protocol.py:137-138`): "`name` is a diagnostic
label for logging and error messages; it is not enforced by
`@runtime_checkable` (which only verifies method presence)."
