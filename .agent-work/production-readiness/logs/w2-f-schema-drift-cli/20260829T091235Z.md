### Decisions

- Keep the existing `DriftReport` and difference dataclasses backward compatible
  (additive only). New difference kinds are added as new dataclass fields and
  dict keys; existing callers using `format_summary()` keep working.
- For schema-wide objects (extensions, RLS policies, functions) the model
  metadata does not track them. Acceptance criteria says "compare"; the only
  authoritative source on the Ferrum side is the migration ledger, which W2-F
  must not edit. So we report live state and let the caller supply an
  `expected_extensions` allowlist for an explicit comparison. RLS policies
  and functions are reported as live-state inventory (no expected set), with
  optional caller-supplied `expected_policies` / `expected_functions` for
  explicit comparison. This is consistent with "Alembic remains
  authoritative, Ferrum checks drift" — the CLI surfaces what is live and
  diffs against model metadata for the things models can express.
- Index comparison compares `Meta.indexes` against `pg_index`, including
  opclass (column class ID → opclass name) and partial predicate (`WHERE`).
  Column names are parsed from `pg_get_indexdef` via a balanced-paren parser.
- Vector dimensions are parsed from `format_type(atttypid, atttypmod)` in
  `pg_attribute`, matching the migration emitter's `VECTOR(N)` shape. The
  introspection query enriches the column dict with `dimensions` when
  available.
- All introspection queries use `$1` bound parameters for the schema name;
  no identifier interpolation. `ferrum_migrations` is always excluded.
- PostgreSQL 18+ stores `NOT NULL` as first-class constraints (`contype='n'`).
  The constraint query uses `pg_constraint.contype IN ('u', 'f', 'c')` to
  exclude NOT NULL constraints (which are an implementation detail of
  `NOT NULL` columns, not model-declarable CHECK constraints).
- Function introspection excludes extension-owned functions (via
  `pg_depend` deptype='e') and aggregate/window/procedure functions
  (via `prokind = 'f'`).
- CLI: `ferrum check-schema` returns exit code 0 when no drift, 1 on drift,
  2 on configuration/connection error (matches `inspectdb` convention).
- Default unmanaged tables (Better Auth, LangGraph, Alembic) are excluded
  by the CLI unless the caller explicitly overrides a category.
