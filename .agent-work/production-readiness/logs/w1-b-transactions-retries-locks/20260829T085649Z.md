### Decisions

1. **Retry contract (§5a binding):**
   - Remove `"connection"` from `_RETRY_CATEGORIES` → only `{"deadlock", "serialization"}` remain.
   - `RetryPolicy` validation rejects `connection` and any other unknown category at construction.
   - `TimedQueryExecutor` gains `is_transaction: bool` (object-scoped: when True, no retry ever).
   - `TimedQueryExecutor` gains `is_write: bool` on `fetch`/`fetchrow`/`fetchval` (default False); `execute` is always `is_write=True`. When `is_write` or `is_transaction`, retry is disabled.
   - `Transaction._require_driver()` passes `is_transaction=True`.
   - QuerySet write terminals (`create`, `bulk_create` w/ returning, `upsert` w/ returning, `bulk_upsert` w/ returning, `update_returning`) pass `is_write=True` on their `fetch`/`fetchrow` calls.

2. **`run_transaction`:**
   - Lives on `Connection` as `run_transaction(fn, *, isolation, readonly, deferrable, deadline, retry)`.
   - `TransactionRetryPolicy` (new dataclass in `runtime.py`): `max_attempts`, `backoff_base`, `backoff_max`, `jitter`. Retries only on `sqlstate` in `{"40001", "40P01"}` — uses W1-D `sqlstate` attribute (no second taxonomy).
   - Opens a fresh `conn.transaction(...)` per attempt. On retriable SQLSTATE → rollback + capped exponential backoff with jitter + retry. On any other error (including `CancelledError`) → rollback + re-raise (no retry). Honors `deadline` via the transaction's own deadline.
   - Callback idempotency: documented as a caller responsibility in the docstring.

3. **`select_for_update`:**
   - Chaining method on `QuerySet`: `select_for_update(*, nowait=False, skip_locked=False, of=())`.
   - `of` accepts `"self"` (model's own table) or relation field names (validated via metadata); resolves to table names for the `FOR UPDATE OF` clause.
   - Post-processes compiled SQL by appending ` FOR UPDATE [OF ...] [NOWAIT] [SKIP LOCKED]` after the existing SQL (PostgreSQL places FOR UPDATE after LIMIT/OFFSET). Identifiers come from validated model metadata — no raw SQL injection.
   - Rejected in `_check_write_scope` (not applicable to UPDATE/DELETE).
   - Applied in `all()` and `first()` (the read terminals that produce rows).

4. **Advisory locks:**
   - `AdvisoryLockKey` (new in `runtime.py`): validates `int` (signed 64-bit) or `(int, int)` (two signed 32-bit halves).
   - Session-scoped: `Connection.advisory_lock(key)` async context manager — pins a connection, takes `pg_advisory_lock`, yields a `Transaction` surface, releases on exit.
   - Transaction-scoped: `Transaction.advisory_xact_lock(key)` and `Transaction.advisory_try_xact_lock(key) -> bool` — use `pg_advisory_xact_lock` / `pg_try_advisory_xact_lock`, auto-released at transaction end.
