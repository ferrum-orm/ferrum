- **Issue:** Docstring promised the deadline is "for the entire run (all

- **Fix chosen:** Option (b) from the verifier — correct the docstring to

  complexity for no consumer-backed requirement. The docstring now states
  the budget is per attempt and not tracked across attempts.
- **Diff:** 4 lines changed in `connection.py` docstring only — no

### Decisions

1. **Docstring fix over implementation change (Finding 1):** The
   per-attempt deadline behavior is safe and matches how
   `asyncio.timeout` wraps each `self.transaction()` block. Tracking
   remaining time across attempts would require wall-clock arithmetic and
   a modified `deadline` contract on `transaction()`, adding complexity
   with no consumer-backed requirement. Correcting the docstring makes the
   contract honest without changing tested behavior. This matches the
   verifier's Option (b).
2. **Remove dead code over comment clarification (Finding 2):** The
   `return "connection"` could never trigger a retry (rejected at
   `RetryPolicy` construction), so it was dead code. Removing it (and the
   contradictory comment) is cleaner than keeping a no-op branch with an
   explanatory comment. The module-level `_RETRY_CATEGORIES` comment
   already documents the §5a rationale.
