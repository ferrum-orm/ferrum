### Material deviations from the task plan

- Used `_StarletteRequest` (eager import with `Any` fallback) instead of
  the `FerrumConnRequest` Protocol for `get_ferrum_conn`/`get_ferrum_transaction`
  parameter types. Reason: FastAPI's dependency injection requires the
  concrete `starlette.requests.Request` type to recognize the parameter as
  the ASGI request object; a `Protocol` is rejected with `FastAPIError:
  Invalid args for response field!`. The `FerrumConnRequest` Protocol is
  retained for static type-checking documentation. The eager import is in
  `ferrum.contrib.fastapi` only (not in `ferrum.contrib.__init__`), so the
  import boundary is preserved.
- Used subprocess-based clean-room import boundary tests instead of
  in-process `sys.modules` snapshots. Reason: the test file itself imports
  `fastapi`/`starlette`, which would pollute `sys.modules` and mask leaks.
  Subprocess tests import core modules in a clean Python process.
- Integration tests use raw ASGI invocation (no `httpx`/`TestClient`).
  Reason: `starlette.testclient.TestClient` requires `httpx`, which is not
  a dev dependency. Raw ASGI with a queue-backed lifespan scope + HTTP
  request helper avoids the extra dependency.

  and raises `ImportError` at construction if missing. Consumers must pin

  `fastapi-users` extra.
