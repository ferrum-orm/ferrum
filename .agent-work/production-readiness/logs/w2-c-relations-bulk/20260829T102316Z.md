### Audit findings (relations.py, 421 lines)

Gaps identified vs task acceptance criteria:

1. **Unbounded prefetch batching**: `prefetch_related_objects` collected ALL parent_ids into one `IN (...)` — exceeds PostgreSQL's 65535 parameter limit.
2. **No ordering in prefetch**: prefetch SQL had no ORDER BY — non-deterministic results.
3. **No nested prefetch**: `prefetch_related("posts__tags")` not supported — only flat one-level.
4. **Composite PK not honored in reverse descriptor**: hardcoded `getattr(obj, "id", None)`.
5. **Reverse OTO stored as list**: `_prefetch_reverse_fk` always stored a list; reverse OTO should store single object or None.
6. **Forward M2M descriptor not installed**: accessing an unloaded forward M2M returned the `ManyToMany` classvar instead of raising.
7. **No cascade documentation**: missing docstrings.
8. **No bulk batch-sizing helper**: no utility for PostgreSQL parameter-limit-aware batch sizing.

### Implementation (relations.py → 685 lines)

All changes in `python/ferrum/relations.py` (import-only from queryset.py/models.py):

1. **`_MAX_PREFETCH_PARAMS` constant** (32768): safe upper bound below PG 65535 and SQLite 32766 limits.
2. **`_chunk_ids()` helper**: splits parent_ids into bounded batches for `IN (...)` clauses. Reads `_MAX_PREFETCH_PARAMS` at call time (not capture time) for test monkeypatching.
3. **`safe_batch_size()` helper**: clamps bulk operation batch sizes to keep total bound parameters under PostgreSQL's 65535 limit.
4. **`_resolve_through_columns()`**: metadata-driven M2M through-table FK column resolution (replaces hardcoded convention).
5. **`_split_nested_prefetch()`**: splits `"posts__tags"` into `("posts", "tags")` for recursive nested prefetch.
6. **`_collect_loaded_related()`**: collects all related objects from a prefetch level for recursive nested prefetch.
7. **`_related_model_for()`**: returns the model class for related objects of a prefetch level.
8. **`prefetch_related_objects()`**: rewritten to support nested `__` syntax, grouped first-level loading (shared prefixes), bounded batching, ORDER BY PK.
9. **`_prefetch_reverse_fk()`**: bounded batching (chunked `IN (...)`), ORDER BY PK, reverse OTO stores single object/None (not list).
10. **`_prefetch_m2m()`**: bounded batching for both through-table and target queries, ORDER BY PK, metadata-driven column resolution.
11. **`install_relation_descriptors()`**: now installs `_ForwardRelationDescriptor` for ALL relation kinds including M2M (was FK/OTO only). Per §5a, forward M2M raises when not loaded.
12. **`_ReverseRelationDescriptor`**: docstring documents §5a contract (reverse FK/OTO → unbound QuerySet, reverse M2M → raises).
13. **Cascade documentation**: module-level docstring documents database-driven cascade behavior (no unit-of-work cascades).
