### Defect 1: False composite-PK docstring (verification Defect 1)

`relations.py` `_ReverseRelationDescriptor` docstring (was lines 269-272)
claimed "Composite primary keys are honored: the unbound QuerySet is filtered
by all PK columns when the parent model uses a composite PK."

The code at `__get__` hardcodes `getattr(obj, "id", None)` and filters by a
single FK column — it does NOT honor composite PKs.

**Fix**: Corrected the docstring to accurately describe the implementation:

> The unbound QuerySet is filtered by the FK column using the parent's ``id``
> field (``getattr(obj, "id")``). Composite primary keys are not yet supported
> — the accessor reads a single ``id`` attribute and filters by one FK column.

### Defect 2: Misleading M2M ordering docstring (verification Defect 2)

Two docstrings claimed "ordered by the target model's PK for deterministic
output" for M2M, but the per-parent M2M list iterates `links[pid]` (through-
table link order from Phase 1, which has no `ORDER BY`), not `by_id` (target
PK order from Phase 2).

**Fix**: Corrected both docstrings:

1. `prefetch_related_objects` (was lines 462-465): scoped the ordering claim
   to reverse-FK; M2M per-parent list order now documented as through-table
   link order.
2. `_prefetch_m2m` (was line 623): corrected to "Target rows are fetched with
   ``ORDER BY PK`` (Phase 2), but per-parent list order follows the through-
   table link order from Phase 1 (which has no ``ORDER BY``), not the target
   PK order."
