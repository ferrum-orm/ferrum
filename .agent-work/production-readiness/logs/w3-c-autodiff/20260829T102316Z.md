### Design decisions

1. `AutodiffSchemaState(SchemaState)` subclasses the existing SchemaState (not
   frozen) and adds: `foreign_keys`, `extensions`, `rls_enabled`, `rls_forced`,
   `policies`, `functions`, `full_text_indexes`. Subclassing (not modifying
   SchemaState) keeps orchestrator.py untouched. Since `compute_plan` accepts
   `SchemaState` via `isinstance`, an `AutodiffSchemaState` IS-A SchemaState
   and the base autodiff path runs unchanged.
2. `build_extended_state(migrations)` replays ALL migration op kinds into the
   extended state — including rename_column, FK, extensions, RLS, policies,
   functions, FTS. This enables round-trip replay tests for every op kind.
3. `compute_autodiff_plan(model_classes, existing_state, *, rename_hints=None)`
   calls the existing `compute_plan` for the base ops (create_table, add_column,
   add_index/drop_index, alter_column for default/nullability, add_fk for new
   tables), then post-processes to add:
   - Column renames (requires explicit `rename_hints`; raises FerrumMigrationError
     without a matching hint — never guesses). Removes the spurious `add_column`
     op that compute_plan emitted for the rename target.
   - Column type changes (emits/merges `alter_column` with `sql_type` —
     destructive per W1-C). Merges into compute_plan's existing alter_column
     ops where possible to avoid duplicate ALTER TABLE statements.
   - FK add/drop on existing tables (compute_plan only handles new tables).
   - Index attribute changes (drop + re-add when unique/using/where/columns
     changed on an existing index).
   - FTS index add/drop (compute_plan does not emit FTS ops at all).
4. Destructive classification: I do NOT re-classify ops. I emit op dicts in the
   exact shape that W1-C's `_is_op_destructive` and `AlterColumn.classification`
   already handle. `alter_column` with `sql_type` set is destructive per W1-C
   (orchestrator.py:169). `rename_column` is safe (not in _DESTRUCTIVE_KINDS).
   `drop_fk` is destructive. `drop_full_text_index` is safe. The plan's
   `destructive`/`requires_confirmation` fields are recomputed via
   `_is_op_destructive` for transparency, but the apply path (orchestrator.py:1371)
   independently scans ops and never trusts the plan flag.
5. Extensions, RLS, functions are NOT model-declarable — there is no model
   metadata to diff against. So `compute_autodiff_plan` does not emit ops for
   them. They are tracked in `AutodiffSchemaState` so that round-trip replay
   tests can verify correct state reconstruction. This satisfies the
   acceptance criterion "Tests: ... extension add/drop, RLS policy changes,
   function changes ... schema-state replay" via state-replay tests, not
   autodiff-emit tests (which would require model metadata that does not exist).
