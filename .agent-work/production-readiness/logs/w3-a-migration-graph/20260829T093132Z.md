### Audit findings (before changes)

Already shipped by W1-C / earlier waves — preserved unchanged:
- `loader._topo_sort` performs Kahn's-algorithm topological sort with deterministic
  `sorted()` tie-breaks and raises `ValueError` on missing dependencies or cycles.
- `loader.scan()` returns `MigrationModule` objects in topo order.
- `base.Migration` declares `dependencies: list[str]` and
  `reverse_operations: list[Operation]` (empty = irreversible).
- `operations.AlterColumn` classifies `not_null=True` or `sql_type is not None` as
  destructive (W1-C).
- `operations.AddIndex(concurrently=True)` is non-transactional (W1-C).
- `orchestrator._is_op_destructive` / `_is_op_non_transactional` and
  `_split_ops_by_phase` are present (W1-C) — used by both `orchestrator.apply()`
  and `cli/migrate_cmd.py`.
- `ledger.verify_checksum` / `verify_checksum_on_conn` enforce W1-C checksums.
- `cli/revert_cmd.py` already implements `--target` downgrade (revert all applied
  migrations strictly after `target`).
- `cli/showmigrations_cmd.py` already renders applied/pending/checksum-mismatch
  status (CLI surface; not orchestrator-level).

Gaps vs the task contract:
1. No orchestrator-level `MigrationGraph` primitive — graph queries (topological
   order, target upgrade/downgrade, status, recovery guidance) exist only as CLI
   ad-hoc code. Adding an orchestrator primitive lets tests and downstream tools
   reason about the graph without a live CLI run.
2. No orchestrator-level reversibility contract helper — `reverse_operations=[]`
   means irreversible is documented on `base.Migration` but not enforced or
   queryable from the orchestrator surface.
3. No `DataMigration` callable type with explicit transaction policy — the only
   way to run data changes today is via `RawSQL` ops, which do not carry a
   "transactional contract" and cannot run arbitrary Python callbacks.
4. No offline-SQL primitive that bundles checksums and phase annotations for
   review/audit without a live DB.
5. No test file dedicated to the migration graph (cycles, target upgrade/
   downgrade, recovery, reversibility, data migrations).

### Decisions

- Add graph logic **additively** to `orchestrator.py` (no rewrite of W1-C apply
  path). The new `MigrationGraph` class wraps `loader.scan()` output plus ledger
  queries and exposes read-only graph views. It does **not** acquire connections
  for apply/revert — those still flow through the W1-C `cli/migrate_cmd.py` /
  `cli/revert_cmd.py` paths. This keeps ADR-004 ownership with W1-C.
- Add `DataMigration` and `run_data_migration` to `orchestrator.py`. The runner
  honors `transaction_policy` (`"required"` / `"none"`). For `"required"` it
  wraps the callable in `conn.transaction()`; for `"none"` it runs in autocommit
  on PostgreSQL and per-op on thin-parity backends. The callable is invoked only
  from developer-authored migration files — `is_trusted=False` raises
  `FerrumMigrationError`. **No automatic source-code execution from untrusted
  files:** the loader already imports developer files via
  `spec.loader.exec_module`; the new code does not change that trust boundary.
- Add `generate_offline_sql` to `orchestrator.py`. Produces a `OfflineSqlPlan`
  dataclass with per-migration sha256 checksum (content-derived, matches the
  ledger's `compute_digest`) and phase annotations (`pre_tx` / `tx` / `post_tx`)
  derived from `_split_ops_by_phase`. No DB I/O.
- Add `is_reversible` / `reverse_classifications` helpers to `base.py`.
- Add `topological_sort` and `detect_cycle` public functions to `loader.py`
  (thin wrappers over `_topo_sort`) so tests and the graph primitive can call
  them without reaching into the private name.
- Do NOT modify `tokens.py`. The checksum mechanism already lives in
  `ledger.compute_digest`; offline-SQL checksums reuse that. Adding anything to
  `tokens.py` would duplicate the surface. (The task allows editing `tokens.py`
  but does not require it.)
