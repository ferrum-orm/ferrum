## Execute

### Decisions

1. **EnableRLS(force=True)** emits `ENABLE ROW LEVEL SECURITY; FORCE ROW LEVEL
   SECURITY` (two statements from one op) so `relrowsecurity` and
   `relforcerowsecurity` are both set. The single-op approach keeps the
   plan-level destructive gate and ledger entry singular.
2. **AlterColumn.classification** returns `"destructive"` for `not_null=True`
   AND `sql_type is not None` (type narrowing). `_is_op_destructive(op)` in
   the orchestrator scans op dicts for `alter_column` with either flag so
   the JSON `apply()` gate catches both cases.
3. **AddIndex(concurrently=True)** emits `CREATE INDEX CONCURRENTLY` (no
   `IF NOT EXISTS` — PostgreSQL rejects the combination) and classifies as
   `"non_transactional"`. Rejected on non-PostgreSQL backends.
4. **Advisory lock**: `pg_advisory_xact_lock(int4, int4)` acquired inside the
   transaction via `conn.acquire()`. Auto-released on commit/rollback so
   cancellation/interruption cannot leak the lock. Lock key derived from
   `sha256(b"ferrum.migrations")`.
5. **Transactional apply**: `_apply_postgres()` pins one connection via
   `conn.acquire()`, wraps all transactional ops + ledger check + ledger
   write in `raw_conn.transaction()`. Non-transactional ops run as pre-tx
   (autocommit before the tx) or post-tx (autocommit after) phases. Plans
   with interspersed non-tx/tx ops are rejected.
6. **lock_timeout / statement_timeout**: validated against
   `^\d+(ms|s|min|h)?$` before `SET LOCAL` inside the tx. Prevents SQL
   injection via the timeout string.
7. **Lock-holder diagnostics**: on lock acquisition failure, queries
   `pg_locks` + `pg_stat_activity` for the advisory lock holder's PID,
   application_name, and state — never query text or bound values.
8. **Ledger**: `_on_conn` variants (`is_applied_on_conn`,
   `record_applied_on_conn`, etc.) run on the pinned raw connection so the
   ledger check and write are on the same connection as the DDL — no race.
   The replay guard now fires for every non-dry-run apply (not just
   token-authenticated ones).
9. **Non-PostgreSQL backends** keep best-effort autocommit-per-op via
   `_apply_thin_parity()` — no advisory lock, no transactional wrap.
10. **Consumer contract tests**: `test_force_rls_alone_enables_and_forces_rls`
    replaces the xfail and verifies both `pg_class.relrowsecurity` and
    `relforcerowsecurity` are true after a single `EnableRLS(force=True)`,
    plus RLS enforcement (zero rows with no GUC) on a non-superuser
    connection. `test_platform_admin_bypass_sees_all_teams` retargeted to use
    a non-superuser role so RLS is actually enforced.
