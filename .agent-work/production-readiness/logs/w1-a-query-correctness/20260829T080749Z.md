## Execute

### 1. Null-equality compilation (`filter(field=None)` → `IS NULL`)

**File: `python/ferrum/queryset.py`** — `_normalize_null_lookup` (line 372)

Extended the existing `_normalize_null_lookup` function to rewrite `eq`+`None` →
`is_null` and `ne`+`None` → `is_not_null`, in addition to the existing
`__is_null=True/False` and `__is_not_null=True/False` handling. This ensures:
- `filter(field=None)` → `IS NULL` (no bound params)
- `filter(field__eq=None)` → `IS NULL`
- `filter(field__ne=None)` → `IS NOT NULL`
- `exclude(field=None)` → `NOT (col IS NULL)` via `~Q` wrapping (semantically `IS NOT NULL`)
- Explicit `__is_null`/`__is_not_null` continue to work unchanged

The rewrite happens before `_validate_lookup`, so the rewritten `is_null`/`is_not_null`
operators are validated against the field allowlist (both are allowed for all field
types per `models.py`).

### 2. Un-`xfail` `danger_delete_all`

### 3. Cast matrix fix (`postgres_value_cast`)

**File: `crates/ferrum-sql/src/emit.rs`** — `postgres_value_cast` (line 1227)

Fixed three cast mismatches that could fail live PostgreSQL:
- `Int` → `integer` (was `bigint`; DDL is `INTEGER`)
- `Float` → `real` (was `double precision`; DDL is `REAL`)
- `ArrayInt` → `integer[]` (was `bigint[]`; DDL is `INTEGER[]`)

The `bigint[]` mismatch was the most critical: the `t.col = v.col` join predicate
in `BulkUpdate` has no implicit cast between `int4[]` and `int8[]`, so it would
fail with `SQLSTATE 42883` (`UndefinedFunction`).

Also changed `ArrayFloat` from `double precision[]` to `float8[]` for DDL
alignment (functionally identical — `FLOAT8` is a PostgreSQL alias for
`double precision`).
