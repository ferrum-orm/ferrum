## Adversarial checks

- **Smoke-install stub effectiveness**: the `cargo`/`rustc` stubs `exit 127` and print an error. If pip falls back to source compile, the stub invocation fails the install step. The pip-log grep for `Building wheel for ferrum-orm` is a second guard. Both are correct. However, the stub only masks `cargo` and `rustc` — if a pre-installed Rust toolchain exists in a non-PATH location that pip/maturin discovers via `RUSTUP_HOME`/`CARGO_HOME` env vars, the stub could be bypassed. In the CI `smoke-install` job, no `RUSTUP_HOME`/`CARGO_HOME` are set and `actions/setup-python` doesn't install Rust, so this is not a practical concern in this workflow. Minor robustness note, not a blocker.
- **cargo-audit version pinning**: the `cargo-audit` job uses `cargo install cargo-audit --locked` without a version pin. The executor noted v0.22.2 requires rustc 1.88 while local rustc is 1.87. The CI `stable` toolchain on `ubuntu-latest` may or may not satisfy v0.22.2's rustc requirement. If the runner's `stable` is < 1.88, `cargo install cargo-audit --locked` would fail to compile v0.22.2. This is a non-deterministic CI risk. Minor defect; recommend pinning `--version 0.22.1` or using a prebuilt binary. Not a blocker for verification (the job structure is correct), but worth a follow-up.
- **attest-build-provenance repo feature**: `actions/attest-build-provenance@v1` requires the GitHub repo to have the artifact attestation feature enabled. If not enabled, the workflow will fail. The executor noted this as a follow-up. Not a W4-D code defect; a repo configuration prerequisite.
