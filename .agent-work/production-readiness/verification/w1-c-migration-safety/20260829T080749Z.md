# Independent verification — W1-C migration execution safety

## Claims under test

Restated from the executor log as falsifiable propositions:

1. **EnableRLS(force=True) emits both ENABLE and FORCE.** A single
   `EnableRLS(table, force=True)` op produces SQL containing both
   `ENABLE ROW LEVEL SECURITY` and `FORCE ROW LEVEL SECURITY`, with ENABLE
   before FORCE.
2. **Live PostgreSQL sets both pg_class flags.** After applying the single
   `force=True` op, `pg_class.relrowsecurity = True` AND
   `pg_class.relforcerowsecurity = True` on a non-superuser non-bypassrls
   connection.
3. **xfail `test_force_rls_without_enable_rls_grants_no_isolation_defect` is
   dropped** and replaced by `test_force_rls_alone_enables_and_forces_rls`
   which verifies both flags on a non-superuser connection.
4. **`alter_column` SET NOT NULL and type narrowing hit the destructive
   confirm gate.** Applying such an op with `confirm=False` raises
   `FerrumMigrationError` before any SQL is executed.
5. **`orchestrator.apply()` uses advisory lock + transactional DDL + atomic
   ledger write on ONE pinned connection.** A failed DDL op rolls back the
   entire transaction including the ledger INSERT.
6. **Replay guard fires for every non-dry-run apply** (not just
   token-authenticated ones). Re-applying the same digest raises
   `[FERR-M003]`.
7. **Non-transactional ops (CREATE INDEX CONCURRENTLY, CREATE EXTENSION) run
   as explicit pre-tx/post-tx phases** and interspersed plans are rejected.
8. **`lock_timeout` / `statement_timeout` are validated** against a strict
   regex; SQL injection via the timeout string is rejected.
9. **No secrets, DSNs, bound values, or row data** in migration output or
   error messages.
10. **No files outside W1-C owned paths were modified.** W1-A/W1-E
    concurrent changes are present but do not touch W1-C scope.
11. **`mise run ci-local` failures are pre-existing** (agent-orchestration
    state drift, type-python pre-existing ty diagnostics, MySQL port
    conflict) and not W1-C regressions.
12. **Revert instructions are sufficient** and the inverse of EnableRLS
    does not reintroduce FORCE-only emission.

## Adversarial checks

### Failed-op rollback (live PostgreSQL)

See §5 above. A multi-statement `RawSQL` op whose first statement succeeds
and second fails still rolls back the entire transaction (including the
first statement's effects and the ledger write). The `async with
conn.acquire() as raw_conn, raw_conn.transaction():` context manager
correctly rolls back on the exception.

### Advisory lock SQL injection

`advisory_lock_sql()` returns `SELECT pg_advisory_xact_lock($1, $2)` with
the keys passed as bound parameters (`ADVISORY_LOCK_KEY_1`,
`ADVISORY_LOCK_KEY_2`). No interpolation. The keys are derived from
`sha256(b"ferrum.migrations")` at import time — not user-supplied.

### Timeout SQL injection

`SET LOCAL lock_timeout = {lock_timeout}` interpolates the value, but
`_validate_timeout` rejects anything not matching `^\d+(ms|s|min|h)?$`
before the `SET LOCAL` is emitted. Verified with `5; DROP TABLE t`,
`'; --`, `5s;`, `abc` — all rejected with `[FERR-M001]`.

### xfail removal

`grep -r test_force_rls_without_enable_rls_grants_no_isolation_defect
tests/consumer_contracts/` returns only binary `.pyc` cache hits — the
source-level xfail is gone. The replacement
`test_force_rls_alone_enables_and_forces_rls` is present and passes on a
non-superuser connection.

### Manifest classification

`ta-16` classification is `SUPPORTED` (line 634). `ta-15`
(`_DEFAULT_VALUE_ALLOWLIST`) remains `FERRUM_DEFECT` (line 580) — consistent
with the task's non-goal of not broadening the allowlist.
