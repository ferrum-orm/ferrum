## Adversarial checks

- **Null-equality edge cases:** `filter(field__gt=None)` is NOT rewritten
  (only `eq`/`ne`+`None`); verified by `test_gt_none_not_rewritten`. `gt`+None
  emits `col > NULL` which is the existing behavior — not a W1-A regression.
- **`exclude(field=None)` shape:** emits `NOT ("col" IS NULL)` rather than the
  literal `IS NOT NULL` substring. Semantically equivalent in PostgreSQL and
  consistent with the existing `exclude(field__is_null=True)` path (the `~Q`
  wrap is the standard `exclude()` mechanism). Not a defect; executor noted it
  as a follow-up in the log.
- **`vector` field `eq` not in allowlist:** `filter(vector_field=None)`
  rewrites `eq`→`is_null` BEFORE `_validate_lookup`, so the missing `eq` in
  vector's allowlist is never checked. Intentional — `= NULL` is never
  correct SQL; `IS NULL` is the only meaningful reading. Consistent with
  Django.
- **`danger_delete_all` guard bypass:** the `danger=True` flag is set on the
  IR operation dict (`queryset.py:3145`), not on the QuerySet. The Rust
  emitter's `MissingFilter` guard is bypassed only for this explicit danger
  API. `delete()` still requires `_is_filtered` (line 3070). No scope leak.
- **Redaction:** the W1-A changes do not touch hook payloads, error
  messages, or exception fields. No new SQL text, bound values, or DSNs are
  logged. The cast comment in `emit.rs` is internal Rust documentation, not
  a runtime payload. Tier A hook contract preserved.
