# Independent verification

## Claims under test

Restated from the executor log and task contract `w3-b-schema-shard-migrations.md`
(acceptance criteria §62-73) as falsifiable propositions:

1. **AC1 — Apply one migration graph across selected schemas/shards.**
   `SchemaShardMigrationCoordinator.run()` iterates a list of `MigrationTarget`
   (each a `(connection, optional schema)` pair) and applies the same
   `modules` list to every target. Falsifiable: a target with a distinct
   connection must receive every pending migration; a target with a schema
   must apply DDL inside `schema_transaction`.
2. **AC2 — Per-target advisory locks (reuse W1-C pattern).** Each target's
   apply acquires `pg_advisory_xact_lock(int4, int4)` with key1 = fixed Ferrum
   namespace and key2 = per-`target_id` hash, inside the apply transaction.
   Falsifiable: lock keys must be stable, signed-int32, distinct per target,
   and distinct from the W1-C `ADVISORY_LOCK_KEY_1` namespace.
3. **AC3 — Bounded concurrency (configurable parallelism).** Non-canary
   targets run with an `asyncio.Semaphore(max_parallelism)` bound. Falsifiable:
   concurrent in-flight applies must never exceed `max_parallelism`.
4. **AC4 — Resumable status (per-target migration state).** The coordinator
   tracks per-(target, migration) state in memory and exposes it via
   `status()`. Falsifiable: a fresh coordinator re-reads the per-target ledger
   and reports already-applied migrations as `SKIPPED`.
5. **AC5 — Fail-fast/continue policy (configurable).** `fail_fast` raises on
   first target failure after recording; `continue` collects all failures and
   returns a full result. Falsifiable: `fail_fast` must raise; `continue` must
   not raise and must include every failure.
6. **AC6 — Never promise cross-shard atomicity; report partial rollout
   precisely.** No cross-target transaction is ever opened. `partial_rollout`
   is True iff some targets made progress and others did not. Falsifiable: no
   `BEGIN` spans two targets; `partial_rollout` is False for all-applied and
   all-skipped, True for mixed.
7. **AC7 — Make reruns idempotent.** Two-level replay guard:
   `MigrationGraph.upgrade_plan()` filters already-applied migrations from
   the per-target ledger; `is_applied_on_conn()` inside the tx catches races.
   Falsifiable: a second run on an already-applied target skips and reports
   no failures.
8. **AC8 — Canary-target support.** `canary_targets` run first, serially. A
   canary failure halts the rollout regardless of policy. Falsifiable: canary
   `target_started` event precedes main `target_started`; canary failure sets
   `halted=True` and main targets report `halted=True`.
9. **AC9 — Structured progress hooks.** `on_progress` receives
   `ProgressEvent` objects for every state transition; sync or async; hook
   errors swallowed. Falsifiable: events emitted in order
   (`COORDINATOR_STARTED` … `COORDINATOR_COMPLETED`); async hook awaited;
   hook exception does not break the rollout.
10. **AC10 — Tests: multi-shard, partial failure, rerun/resume, canary,
    concurrency.** Falsifiable: the named test files exist and pass against
    live PostgreSQL.
