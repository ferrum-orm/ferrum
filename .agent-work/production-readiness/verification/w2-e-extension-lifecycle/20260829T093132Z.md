## Adversarial checks

### Doc/implementation mismatch (DEFECT-1, medium)

`PgVectorInitializer` class docstring at `python/ferrum/ext/pgvector.py:126-129`
states:

> "Runs `CREATE EXTENSION IF NOT EXISTS vector` through the sanctioned
> `conn._require_driver().execute(...)` seam (never exposes the raw asyncpg
> pool to consumer code)."

The actual implementation at `python/ferrum/ext/pgvector.py:187` uses
`await pool.execute(...)` — the raw asyncpg pool — not
`conn._require_driver().execute(...)`. The executor log acknowledges this
in the "Risks and follow-up" section ("The pgvector initializer reaches
`conn._driver._pool.execute(...)` for `CREATE EXTENSION` (preserving the
existing `register_vector_codecs` behavior...)"), but the public-facing
class docstring still claims the sanctioned seam.

The same inconsistency appears in the `ConnectionInitializer` protocol
docstring at `python/ferrum/drivers/protocol.py:97-99`:

> "Implementations use `conn._require_driver()` and `conn.dialect`, the
> same sanctioned seams QuerySet terminals and migrations use."

The canonical `PgVectorInitializer` implementation uses `conn._driver`
(the raw attribute, not the `_require_driver()` method) and `pool.execute`
(the raw pool, not the driver's `execute`).

This is a documentation defect, not a code-behavior defect. The code
preserves the existing `register_vector_codecs` behavior (which also used
`pool.execute`), and all unit + integration tests pass. The unit test
`TestConsumerDefinedInitializer.test_citext_style_initializer_uses_sanctioned_seam`
demonstrates the *intended* pattern (`conn._require_driver().execute(...)`)
for consumer-defined initializers, but the pgvector initializer itself
does not follow that pattern.

**Severity**: medium. The misleading docstring could lead a consumer to
assume the pgvector initializer never touches the raw pool, which is
false. It also creates a discrepancy between the protocol contract
("implementations use `conn._require_driver()`") and the canonical
implementation.

**Affected acceptance criterion**: C2 (PgVectorInitializer) — the
docstring claims a property the code does not deliver.

**Smallest required correction**: Either (a) update the
`PgVectorInitializer` class docstring and the `ConnectionInitializer`
protocol docstring to accurately describe the `pool.execute` path
(which is the existing, behavior-preserving path), or (b) route the
`CREATE EXTENSION` through `conn._require_driver().execute(...)` and
update the existing `test_pgvector_score.py` mocks (a shared path —
requires a coordinator lease on `tests/python/unit/test_pgvector_score.py`).
Option (a) is the smaller, owned-paths-only fix.

### Protocol `name` attribute requirement (DEFECT-2, low)

The `ConnectionInitializer` protocol declares `name: str` as a class-level
annotation. `@runtime_checkable` Protocol membership checks only verify
method presence, not attribute presence — `hasattr(init, "name")` is not
enforced by `isinstance`. The unit test `test_protocol_requires_name_and_initialize`
verifies a `CitextInitializer` with both members passes `isinstance`, and
`test_missing_initialize_is_not_an_initializer` verifies a class without
`initialize` fails. No test verifies a class with `initialize` but without
`name` fails `isinstance` (it would not — `runtime_checkable` only checks
methods). This is a known Protocol limitation, not a code defect, but the
protocol docstring should note that `name` is a documentation/diagnostics
convention rather than an enforced member.

**Severity**: low. The contract is documented; the runtime check is
best-effort for attributes. No behavior impact.

**Affected acceptance criterion**: C1 (ConnectionInitializer protocol).

**Smallest required correction**: Add a one-line note to the protocol
docstring clarifying that `name` is a diagnostic label, not enforced by
`runtime_checkable` (which only verifies methods).

### `if driver is None or pool is None` ordering (DEFECT-3, low, pre-existing)

`python/ferrum/ext/pgvector.py:174-176` reads `driver = conn._driver` then
`pool = getattr(driver, "_pool", None)` then `if driver is None or pool
is None:`. If `driver is None`, `getattr(driver, "_pool", None)` returns
`None` (the default), so the condition is correctly evaluated. This is
pre-existing behavior preserved verbatim from the original
`register_vector_codecs`; not introduced by W2-E. Noting for completeness.

**Severity**: low, pre-existing. Not a W2-E regression.
