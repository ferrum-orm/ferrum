# Independent verification — W1-D error taxonomy and diagnostics

## Claims under test

Restated from the executor log as falsifiable propositions:

1. **C1 — Sanctioned fields on base class**: `FerrumError` declares
   `sqlstate`, `category`, `constraint`, `model`, `operation` and `__init__`
   accepts them as keyword-only args.
2. **C2 — Every mapped exception carries `sqlstate` and `category`**: every
   branch of `map_db_error` and `map_native_error` produces an exception with
   non-`None` `category` (where applicable) and a structured `sqlstate`.
3. **C3 — Closed category enum**: `ERROR_CATEGORIES` is a `frozenset[str]`
   covering the §5a-required PostgreSQL classes (integrity, schema,
   serialization, deadlock, lock_timeout, query_cancellation,
   invalid_transaction_state, failover, connection, timeout, pool_exhaustion,
   undefined_function, ...) plus Ferrum-level categories.
4. **C4 — New asyncpg mappings**: deadlock, serialization, lock_timeout,
   failover (admin/crash/cannot_connect), invalid_transaction_state,
   pool_exhaustion, undefined_function, query_cancellation are mapped.
5. **C5 — Tier-A hook category**: `_TIER_A_KEYS` includes `category`;
   `query_failure`/`hydration_failure` accept an optional `category`;
   `QueryTimer.__exit__` extracts `category` from `FerrumError`.
6. **C6 — Single redaction boundary**: `map_db_error`/`map_native_error`
   remain the only redaction seam; `_extract_context` threads only
   `model`/`operation` (never bound values, DETAIL, HINT, DSN, row data).
7. **C7 — No leak**: DETAIL/HINT/bound values/row data/DSNs never appear in
   any exception attribute, message, or default (Tier-A) hook payload.
8. **C8 — Live PostgreSQL**: unique violation carries `sqlstate=23505` and
   `category`; not-null violation carries `category`; hook payload excludes
   the bound value "dup".
9. **C9 — Scope**: only the 8 owned files were changed; `crates/ferrum-pyo3/`
   untouched (executor correctly noted no Rust change needed).
10. **C10 — Revert**: instructions restore owned files from base revision and
    preserve unrelated working-tree changes.
