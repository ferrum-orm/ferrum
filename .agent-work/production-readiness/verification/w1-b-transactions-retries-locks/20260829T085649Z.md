## Adversarial checks

### SQL safety (select_for_update)

- `_append_for_update_clause` constructs `FOR UPDATE OF "table1", "table2"`
  where table names come from `of_tables`, which are resolved from model
  metadata relation field names or literal `"self"` → `metadata.table_name`.
  No user-supplied identifiers reach the SQL string.
- `nowait` and `skip_locked` are boolean flags appending literal `NOWAIT` /
  `SKIP LOCKED` — no user input.
- Non-postgres dialects are rejected with `FerrumConfigError` before SQL
  emission (`queryset.py:291-295`).

### SQL safety (advisory locks)

- All advisory lock SQL uses `$N` positional parameters with explicit casts.
  `AdvisoryLockKey.as_args()` returns validated ints. No identifier
  interpolation in any advisory lock SQL.

### Retry scope — write duplication

- `execute` is always `is_write=True` → `retry = None` → no statement retry.
- QuerySet write terminals with RETURNING pass `is_write=True` on
  `fetch`/`fetchrow` → no statement retry.
- `Transaction`-pinned executor has `is_transaction=True` → `retry = None`
  → no statement retry.
- `run_transaction` replays the entire callback in a fresh transaction per
  attempt — this is the sanctioned write-retry story. Callback idempotency
  is documented as caller responsibility.

### Advisory lock key validation

- `AdvisoryLockKey` rejects `bool` (subclass of int), non-int, bad tuple
  length, overflow (64-bit int, 32-bit tuple halves). Unit tests cover all
  rejection paths.

## Decision

**changes_required**

### Findings

#### FINDING 1 (minor): `run_transaction` deadline semantics don't match docstring

- **Severity:** minor
- **Evidence:** `connection.py:643-645` docstring states deadline is "for the
  entire run (all attempts combined)." Implementation at `connection.py:664`
  passes the same `deadline` value to each `self.transaction(deadline=deadline)`
  call, giving each attempt the full budget rather than tracking remaining
  time across attempts. If `deadline=5.0` and attempt 1 takes 4.9s before
  failing with 40001, attempt 2 gets another 5.0s, making total run time up
  to ~10s+backoff.
- **Affected criterion:** `run_transaction` matches §5a ("honor
  cancellation/deadline"). The §5a contract says "honor cancellation/deadline"
  without specifying total vs. per-attempt; the implementation honors it
  per-attempt, which is safe but doesn't match the docstring's "all attempts
  combined" promise.
- **Required correction:** Either (a) track elapsed time across attempts and
  pass `remaining = deadline - elapsed` to each `self.transaction()`, or (b)
  correct the docstring to say "per-attempt deadline" instead of "for the
  entire run (all attempts combined)."

#### FINDING 2 (cosmetic): Contradictory comment in `_exception_category`

- **Severity:** cosmetic
- **Evidence:** `runtime.py:66-68` comment says "connection is intentionally
  NOT returned here" but `runtime.py:69` returns `"connection"` for generic
  Python exceptions (`TimeoutError`, `asyncio.TimeoutError`,
  `ConnectionError`, `OSError`). The comment refers to the removed asyncpg
  `PostgresConnectionError` check, not the generic Python exception check
  below it.
- **Affected criterion:** none (functionally harmless —
  `RetryPolicy.__post_init__` rejects `"connection"` in `on` because
  `_RETRY_CATEGORIES` doesn't include it, so the returned category can never
  trigger a retry).
- **Required correction:** Either remove the `return "connection"` line
  (dead code for retry purposes) or clarify the comment to distinguish the
  removed asyncpg check from the remaining generic Python exception check.

### Additional observations (not defects)

- **`# type: ignore` on `is_write` calls (5 sites in `queryset.py`):**
  `QueryExecutorProtocol` in `drivers/protocol.py` (not owned by W1-B) does
  not declare the `is_write` keyword arg. Runtime behavior is correct (the
  object is always a `TimedQueryExecutor` which accepts `is_write`). Follow-up
  for a future workstream to update the protocol.
- **`select_for_update` SQL post-processing in Python:** FOR UPDATE is
  appended to compiled SQL in Python, not Rust. Identifiers come from
  validated model metadata. Follow-up for a future workstream to add FOR
  UPDATE to the Rust IR.
- **No integration test for real 40001/40P01 replay:** The `run_transaction`
  replay is tested at the unit level with fake drivers raising
  `FerrumDatabaseError(sqlstate="40001"/"40P01")` and confirmed live via a
  verification script. A real serialization failure would produce the same
  `sqlstate` attribute via W1-D error mapping, so this is sufficient evidence.
