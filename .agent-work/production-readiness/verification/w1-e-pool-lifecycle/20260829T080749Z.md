## Claims under test

Each acceptance criterion from `.agent-work/production-readiness/tasks/w1-e-pool-lifecycle.md`
restated as a falsifiable proposition against fresh evidence.

1. **C1 — acquire_timeout on every acquire path**: `fetch`, `fetchrow`, `fetchval`,
   `execute`, `transaction()`, `open_stream()`, and the explicit `acquire()` context
   manager all honor `acquire_timeout`. Disprove by finding any path that calls
   `pool.acquire()` without forwarding the timeout.
2. **C2 — Distinct idle lifetime vs hard max age**: `max_idle_lifetime` (idle
   recycling) and `max_connection_age` (hard max age) are separate config knobs with
   distinct semantics; legacy `max_lifetime` aliases `max_idle_lifetime`.
3. **C3 — New config knobs**: `command_timeout`, `statement_cache_size`, `ssl`,
   `server_settings`, `application_name` are wired to `asyncpg.create_pool()`.
4. **C4 — Failover-safe replacement; no unconditional pre-ping**: Stale
   connections are recycled only on detected failover-category errors via
   `expire_connections()`; there is no per-query pre-ping.
5. **C5 — Event-based shutdown; drain timeout; close streams**: `close()` uses an
   `asyncio.Event` (not a busy-poll loop) to wait for in-flight work; forced drain
   timeout is reported; active streams are closed; no connection leak.
6. **C6 — Typed PoolStats**: `PoolStats` is a typed dataclass with `size`, `idle`,
   `acquired`, `waiters`, `min_size`, `max_size`, `inflight`, `accepting`, `closing`.
7. **C7 — Tests**: saturation, cancellation, failover/restart (simulated), stale
   connection, growth, shutdown.
8. **C8 — DSN redaction (§3)**: pool error paths and connection diagnostics never
   include the password, full DSN, bound parameter values, or PostgreSQL
   DETAIL/HINT.
9. **C9 — Structured category (§5a)**: pool-exhaustion and failover errors carry
   `category` from the W1-D error taxonomy.
10. **C10 — No scope leak**: only W1-E owned paths changed.
11. **C11 — Revert instructions sufficient**: owned files restorable from base
    revision; unrelated work preserved.

- **C1 — acquire_timeout enforcement** (`python/ferrum/drivers/postgres.py`):
  - `_acquire_cm()` (lines ~388-396) is the single seam: returns
    `pool.acquire(timeout=self._acquire_timeout)` when set, else `pool.acquire()`.
  - `fetch` (line 416), `fetchrow` (line 423), `fetchval` (line 430), `execute`
    (line 426) all use `async with self._acquire_cm() as raw_conn` — confirmed.
  - `transaction()` (lines 499-511) uses `pool.acquire(timeout=...)` directly with
    the same `if self._acquire_timeout is not None` branch — confirmed.
  - `open_stream()` (lines 444-451) uses `pool.acquire(timeout=...)` directly with
    the same branch — confirmed.
  - `acquire()` context manager (lines 464-466) uses the same branch — confirmed.
  - Every acquire path forwards the timeout. C1 PASS.
- **C2 — idle vs max age** (`postgres.py:223-244`): `max_idle_lifetime` takes
  precedence over legacy `max_lifetime`; both map to asyncpg
  `max_inactive_connection_lifetime`. `max_connection_age` is tracked separately
  via `_conn_birth_times` in the init callback (line 291) and enforced via
  `expire_connections()`. C2 PASS.
- **C3 — config knobs** (`postgres.py:267-279`): `command_timeout`,
  `statement_cache_size`, `ssl`, `server_settings` are wired to
  `pool_kwargs`. `application_name` is folded into `server_settings` via
  `setdefault` (line 245). C3 PASS.
- **C4 — failover-safe** (`postgres.py:405-415`): `_handle_post_error` checks
  `getattr(mapped, "category", None) == "failover"` and only then calls
  `_expire_connections_safe()`. No per-query pre-ping in any path. C4 PASS.
- **C5 — event-based shutdown** (`connection.py:101-145`): `_EventLifecycleGuard`
  subclasses `_LifecycleGuard` (from `runtime.py`, NOT owned by W1-E) and uses
  `asyncio.Event` (`_drained`). `begin()` clears, `end()` sets when
  `_inflight == 0`. `wait_drained(timeout=...)` uses
  `asyncio.wait_for(self._drained.wait(), timeout=timeout)`. `close()`
  (`connection.py:307-336`) calls `wait_drained`, then closes the pool, and raises
  `FerrumTimeoutError(category="timeout")` if not drained. `AsyncpgDriver.close()`
  (`postgres.py:340-352`) uses `pool.terminate()` when connections are still
  acquired (after drain timeout) to avoid a deadlock — no leak. `drain_inflight`
  import removed from `connection.py`. C5 PASS.
- **C6 — PoolStats** (`postgres.py:151-187`): `@dataclass(frozen=True)` with
  exactly the fields: `size`, `idle`, `acquired`, `waiters`, `min_size`,
  `max_size`, `inflight`, `accepting`, `closing`. Verified via
  `dataclasses.fields(PoolStats)` — no missing, no extra. `waiters` is `-1`
  sentinel when asyncpg doesn't expose it. C6 PASS.

## Findings

### F1 — Minor: no integration test for `open_stream` + `acquire_timeout`

- Severity: minor
- Evidence: `grep -rn "open_stream" tests/python/integration/` returns no
  matches. The implementation enforces `acquire_timeout` on `open_stream`
  (`postgres.py:444-451`), but there is no integration test that saturates the
  pool and verifies `open_stream` honors the timeout.
- Affected criterion: C1 (test coverage, not implementation).
- Smallest required correction: add an integration test that saturates a
  `max_size=1` pool and verifies `open_stream` raises `FerrumTimeoutError`
  on acquire timeout. This does not block verification — the implementation
  is correct and the acceptance criterion is satisfied at the implementation
  level.

### F2 — Note: `release()` does not call `_handle_post_error`

- Severity: informational (not a defect)
- Evidence: `AsyncpgDriver.release()` (`postgres.py:475-480`) calls
  `map_db_error` but does not call `_handle_post_error`. Release is not an
  acquire path, and a release failure is unlikely to be a failover scenario.
  No correction required.

### F3 — Note: `PoolStats.waiters` is always `-1`

- Severity: informational (documented limitation)
- Evidence: asyncpg does not expose the waiter count. The dataclass docstring
  documents the `-1` sentinel. No correction required.

### F4 — Note: `max_connection_age` enforcement is best-effort

- Severity: informational (documented limitation)
- Evidence: birth times are tracked in the init callback, but enforcement is
  via `expire_connections()` (manual or failover-triggered), not automatic
  acquire-time enforcement. The executor log documents this as the minimal
  implementation. No correction required for v0.1.
